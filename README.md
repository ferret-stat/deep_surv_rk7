# Прогнозирование оттока клиентов с помощью DeepSurv

## Описание проекта

Проект посвящён оценке риска оттока клиентов с использованием методов анализа выживаемости и нейронной сети на основе подхода **Cox Proportional Hazards (DeepSurv)**.

### Цель проекта

Построить модель, которая оценивает относительный риск оттока клиентов и помогает анализировать, как долго клиент остаётся активным.

В отличие от обычной бинарной классификации, анализ выживаемости учитывает время до наступления события, а также наблюдения, в которых событие ещё не произошло (цензурированные наблюдения).

## Что сделано

- Загрузка и объединение данных о клиентах, посещениях, купонах и предпочтениях.
- Подготовка признаков: обработка пропусков, кодирование категориальных переменных и масштабирование числовых признаков.
- Разделение данных на обучающую и тестовую выборки.
- Построение нейронной сети на TensorFlow/Keras с регуляризацией и Dropout.
- Реализация функции потерь на основе частичного правдоподобия Кокса.
- Оценка качества модели с помощью C-index.
- Анализ кривых выживаемости Каплана — Мейера, групп риска и калибровки прогноза.

## Результаты

На тестовой выборке получено значение **C-index = 0.738**.

C-index оценивает, насколько хорошо модель ранжирует объекты по риску наступления события. Более высокое значение указывает на лучшее ранжирование клиентов по относительному риску.

При этом C-index сам по себе не гарантирует точность предсказанных вероятностей или готовность модели к использованию в реальном бизнесе. Для этого необходимы дополнительные проверки качества, устойчивости и калибровки.

## Данные

### Описание основного датафрейма

Основной датафрейм содержит записи о клиентах и признаки, описывающие их уровень, контактные данные, историю посещений и платежей, а также целевые переменные для анализа времени до наступления события.

| Поле               | Описание                                                                                                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PEOPLE_ID`        | Идентификатор клиента.                                                                                                                                                                                         |
| `LVL`              | Уровень или категория клиента в исходной системе. Точные значения определяются правилами проекта.                                                                                                              |
| `mobile`           | Номер мобильного телефона или поле, связанное с мобильным контактом. Формат зависит от исходных данных.                                                                                                        |
| `TELEGRAM`         | Поле, связанное с Telegram-контактом клиента, например идентификатор или контактные данные.                                                                                                                    |
| `last_visit`       | Дата последнего посещения клиента.                                                                                                                                                                             |
| `first_in_periods` | Первый период, в котором клиент появился в анализируемых данных.                                                                                                                                               |
| `visit_cnt`        | Количество посещений клиента за анализируемый период.                                                                                                                                                          |
| `total_paysum`     | Общая сумма платежей клиента за анализируемый период.                                                                                                                                                          |
| `avg_paysum`       | Средняя сумма платежа клиента.                                                                                                                                                                                 |
| `avg_days_between` | Средний интервал между посещениями в днях.                                                                                                                                                                     |
| `duration`         | Длительность наблюдения до наступления события или окончания периода наблюдения. Используется как временная переменная в анализе выживаемости.                                                                 |
| `recency`          | Давность последнего посещения относительно даты отсчёта, обычно в днях.                                                                                                                                        |
| `event`            | Индикатор наступления события. В анализе выживаемости значение `1` обычно означает, что событие произошло, а `0` — цензурированное наблюдение. Точное определение события необходимо проверить в коде проекта. |

### Роль данных в модели

- **Признаки клиента:** `LVL`, `visit_cnt`, `total_paysum`, `avg_paysum`, `avg_days_between` и другие поля, выбранные на этапе подготовки данных.
- **Временная переменная:** `duration` задаёт время наблюдения до события или окончания периода наблюдения.
- **Целевая переменная:** `event` указывает, произошло ли целевое событие.
- **Идентификатор:** `PEOPLE_ID` используется для идентификации клиента и обычно исключается из признаков модели.
- **Контактные данные:** `mobile` и `TELEGRAM` могут содержать персональную информацию и не должны использоваться в качестве признаков без обоснованной необходимости.

> **Важно:** точные единицы измерения и правила формирования `first_in_periods`, `duration`, `recency` и `event` зависят от логики подготовки данных в ноутбуке. Описания выше основаны на названиях столбцов и должны быть сверены с кодом проекта.
