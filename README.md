Прогнозирование оттока клиентов с помощью DeepSurv
Проект посвящён оценке риска оттока клиентов с использованием методов анализа выживаемости и нейронной сети на основе подхода Cox proportional hazards (DeepSurv).
Цель проекта
Построить модель, которая оценивает относительный риск оттока и помогает анализировать, как долго клиент остаётся активным. В отличие от обычной бинарной классификации, анализ выживаемости учитывает время до события и наблюдения, в которых событие ещё не произошло (цензурированные наблюдения).
Что сделано

- Загрузка и объединение данных о клиентах, посещениях, купонах и предпочтениях.
- Подготовка признаков: обработка пропусков, кодирование категориальных переменных и масштабирование числовых признаков.
- Разделение данных на обучающую и тестовую выборки.
- Построение нейронной сети на TensorFlow/Keras с регуляризацией и Dropout.
- Реализация функции потерь на основе частичного правдоподобия Кокса.
- Оценка модели с помощью C-index.
- Анализ кривых выживаемости Каплана — Мейера, групп риска и калибровки прогноза.
  Результат
  В ноутбуке получено значение C-index = 0.738 на тестовой выборке.
  C-index оценивает, насколько хорошо модель ранжирует объекты по риску события: более высокое значение означает лучшее ранжирование. Этот показатель сам по себе не гарантирует точность вероятностей или готовность модели к использованию в реальном бизнесе.

  Установка и запуск
  Рекомендуется использовать отдельное виртуальное окружение. В примере ниже используется Python 3.10; совместимость конкретных версий библиотек зависит от операционной системы и окружения.

1. Создайте виртуальное окружение
   Windows:
   python -m venv .venv
   .venv\Scripts\activate
   macOS / Linux:
   python3 -m venv .venv
   source .venv/bin/activate
2. Установите зависимости
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   Обратите внимание: scikit-survival может иметь дополнительные требования к совместимости с версией Python и установленными научными библиотеками. Если установка завершится ошибкой, подберите совместимые версии для вашей среды.
3. Добавьте данные
   Поместите необходимые .pkl-файлы в папку datasets/ в соответствии с путями, указанными в ноутбуке.
4. Запустите Jupyter
   jupyter notebook
   Откройте ноутбук проекта и выполните ячейки последовательно.
   Данные
   Описание входного датафрейма
   Основной датафрейм содержит по одной записи на клиента и признаки, описывающие его уровень, контакты, историю посещений и платежей, а также целевые переменные для анализа времени до события.
   Поле Описание
   PEOPLE_ID Идентификатор клиента.
   LVL Уровень или категория клиента в исходной системе. Точное значение категорий определяется правилами проекта.
   mobile Номер мобильного телефона или признак/поле, связанное с мобильным контактом; формат зависит от исходных данных.
   TELEGRAM Поле, связанное с Telegram-контактом клиента (например, идентификатор или контактные данные).
   last_visit Дата последнего посещения клиента.
   first_in_periods Первый период, в котором клиент появился в анализируемых данных.
   visit_cnt Количество посещений клиента за анализируемый период.
   total_paysum Общая сумма платежей клиента за анализируемый период.
   avg_paysum Средняя сумма платежа клиента.
   avg_days_between Средний интервал между посещениями в днях.
   duration Длительность наблюдения до события или окончания периода наблюдения; используется как временная переменная в survival analysis.
   recency Давность последнего посещения относительно даты отсчёта, обычно в днях.
   event Индикатор наступления события: в задачах анализа выживаемости обычно 1 означает, что событие произошло, а 0 — цензурированное наблюдение. Проверьте код проекта, чтобы подтвердить, что именно считается событием.

Роль данных в модели

- Признаки клиента: LVL, visit_cnt, total_paysum, avg_paysum, avg_days_between и другие поля, выбранные на этапе подготовки данных.
- Временные и целевые поля: duration задаёт время наблюдения, а event — факт наступления целевого события. PEOPLE_ID обычно используется как идентификатор, а не как признак модели.
- Поля контактов: mobile и TELEGRAM могут содержать персональные данные. Перед публикацией репозитория удалите или обезличьте их, если в проекте есть реальные контактные сведения.
- Важно: точные единицы измерения, правила формирования first_in_periods, duration, recency и кодировка event зависят от логики подготовки данных в ноутбуке. Описания выше основаны на названиях столбцов и должны быть сверены с кодом проекта. и конфиденциальность
